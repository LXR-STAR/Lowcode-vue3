# DevFlow 低代码平台学习文档

## 📚 快速上手（1-2天学习计划）

### 第一天：项目架构与核心功能

#### 1. 项目概览

**项目定位**：基于 Vue3 + TypeScript 的可视化页面搭建平台，支持拖拽组件快速生成页面。

**技术栈**：
- Vue 3 + TypeScript
- Vite (构建工具)
- Pinia (状态管理)
- Element Plus (UI组件库)
- ECharts (图表库)
- Vue Router (路由)

**核心功能**：
- 组件拖拽与编辑
- 撤销/重做
- 属性配置
- 事件系统
- 数据绑定
- Schema 导出/导入
- 代码生成
- 独立渲染器

#### 2. 项目架构

**目录结构**：
```
src/
├── components/          # 组件
│   ├── editor/         # 编辑器核心组件
│   └── components/     # 基础组件库
├── stores/             # Pinia 状态管理
├── types/              # TypeScript 类型定义
├── utils/              # 工具函数
├── renderer/           # 独立渲染器
├── views/              # 页面视图
└── packages/           # 独立包
    └── renderer/       # 渲染器 npm 包
```

**核心数据流**：
1. **组件拖拽** → `CanvasArea.vue` → `componentStore.addComponent()`
2. **属性编辑** → `PropertyPanel.vue` → `componentStore.updateComponentProps()`
3. **事件配置** → `EventPanel.vue` → `eventStore.updateEvent()`
4. **数据绑定** → `DataBindingPanel.vue` → `dataSourceStore.updateDataSource()`
5. **历史记录** → 操作触发 → `historyStore.saveSnapshot()`

**状态管理**：
- `component.ts` - 组件管理
- `editor.ts` - 编辑器状态
- `history.ts` - 历史记录
- `event.ts` - 事件系统
- `dataSource.ts` - 数据源管理

### 第二天：技术实现与面试准备

#### 3. 核心技术实现

**3.1 设计器与渲染器分离**
- **实现**：独立的 `@devflow/renderer` npm 包
- **文件**：`packages/renderer/`
- **关键点**：
  - Schema JSON 规范定义
  - 异步组件加载
  - 外部依赖作为 peerDependencies

**3.2 动态组件渲染引擎**
- **实现**：`RenderComponent.vue` + 组件映射
- **文件**：`components/editor/RenderComponent.vue`
- **关键点**：
  - `component :is` 动态组件
  - 递归渲染子组件
  - 组件映射表 `componentMap`

**3.3 性能优化**
- **实现**：`shallowRef` + 不可变数据 + 防抖
- **文件**：`stores/component.ts`、`stores/history.ts`
- **关键点**：
  - `shallowRef<EditorComponent[]>([])` 避免深度响应式
  - 组件更新时创建新数组 `components.value = [...components.value]`
  - 历史记录保存防抖 `setTimeout(() => performSave(), 300)`

**3.4 撤销/重做功能**
- **实现**：快照模式 + 栈结构
- **文件**：`stores/history.ts`
- **关键点**：
  - 每次操作保存组件树深拷贝
  - 限制最大历史记录 50 步
  - 支持 `undo()` 和 `redo()`

**3.5 事件系统与数据绑定**
- **实现**：事件 DSL + 数据绑定配置
- **文件**：`types/events.ts`、`types/dataSource.ts`
- **关键点**：
  - 事件类型：click、dblclick、mouseenter 等 8 种
  - 动作类型：navigate、showMessage、setVariable 等 7 种
  - 数据源：静态数据、API 接口、全局变量

**3.6 画布交互**
- **实现**：拖拽 + 缩放 + 旋转 + 对齐
- **文件**：`components/editor/CanvasArea.vue`
- **关键点**：
  - 坐标转换：`(clientX - rect.left - offsetX) / scale`
  - 对齐辅助线：检测与其他组件的对齐点
  - 网格吸附：`snapToGridValue()`

#### 4. 亮点与难点

**核心亮点**：
1. **架构设计** - 设计器与渲染器分离，可独立集成
2. **性能优化** - shallowRef + 不可变数据 + 防抖
3. **事件系统** - 可视化配置，安全执行
4. **完整交互** - 拖拽、缩放、旋转、对齐
5. **扩展性** - 组件注册表，支持自定义组件

**技术难点**：
1. **坐标转换** - 缩放时的鼠标位置计算
2. **递归渲染** - 容器组件的无限嵌套
3. **历史记录** - 性能与内存的平衡
4. **事件安全** - 避免 eval 执行代码

#### 5. 面试高频问题

**Q1: 项目的核心架构是什么？**
- **A**：采用设计器与渲染器分离架构，设计统一的 Schema JSON 规范，将渲染器封装为独立 npm 包，支持多项目集成复用。

**Q2: 如何处理组件的嵌套渲染？**
- **A**：通过 `RenderComponent.vue` 递归渲染子组件，使用 `component :is` 动态加载组件类型，配合 `children` 字段实现无限嵌套。

**Q3: 性能优化做了哪些工作？**
- **A**：
  1. 使用 `shallowRef` 管理组件列表，避免深度响应式追踪
  2. 组件更新采用不可变数据模式，创建新数组触发响应
  3. 历史记录保存引入防抖机制（300ms），避免频繁操作产生过多快照

**Q4: 撤销/重做如何实现？**
- **A**：采用快照模式，每次操作保存一份组件树的深拷贝，使用栈结构管理历史记录，支持 50 步操作回溯，超出时自动移除最早的记录。

**Q5: 事件系统如何保证安全？**
- **A**：设计事件 DSL，不存储 JS 代码字符串，而是用 `{ type: 'navigate', config: { url: '...' } }` 格式描述动作，在渲染端通过 `switch-case` 安全解析执行。

**Q6: 画布缩放时如何处理坐标？**
- **A**：使用逆矩阵计算：`canvasX = (clientX - rect.left - offsetX) / scale`，将屏幕坐标转换为画布坐标，确保缩放时拖拽定位准确。

**Q7: 如何支持数据绑定？**
- **A**：实现数据绑定引擎，支持三种数据源：静态数据、API 接口、全局变量，通过配置界面可视化绑定到组件属性。

**Q8: 渲染器如何独立打包？**
- **A**：单独的 `packages/renderer` 目录，配置 `vite.config.ts` 为库模式，外部依赖作为 peerDependencies，支持 ES Module 和 UMD 格式。
