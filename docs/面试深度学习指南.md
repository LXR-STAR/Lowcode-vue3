## 亮点一：设计器与渲染器分离架构

### 核心概念

- **设计器**：在网页上拖拽组件、改样式、加事件、绑数据，最后生成一段 Schema JSON
- **渲染器**：解析 JSON，让 JSON 在页面完整渲染出来，无编辑逻辑
- **Schema JSON**：设计器和渲染器之间的"协议"，两者只通过这个 JSON 通信

### 1.1 为什么这样做？

**问题背景**：

- 传统低代码项目，设计器和渲染器耦合在一起，无法复用
- 其他项目想使用同样的渲染能力，需要复制大量代码
- 渲染逻辑和编辑逻辑混杂，代码难以维护

**解决方案**：

- 将渲染器独立出来，作为单独的 npm 包
- 设计统一的 Schema JSON 规范，作为设计器和渲染器的"协议"
- 设计器负责生成 Schema，渲染器负责解析 Schema 渲染页面

**类比理解**：
> 就像前端和后端通过 API 接口通信一样，设计器和渲染器通过 Schema JSON 通信。
> 设计器 = 后台管理系统（生产数据），渲染器 = 前端页面（消费数据），Schema = API 接口（数据格式）

### 1.2 具体实现

**Schema JSON 规范设计**：

```typescript
// 页面 Schema 结构 - 最外层
interface SchemaPage {
  version: string              // 版本号，用于兼容性检查
  name: string                 // 页面名称
  canvas: SchemaCanvas         // 画布配置（宽高、背景色）
  components: SchemaComponent[] // 组件列表（核心）
  events: EventBinding[]       // 事件配置
  dataSources: DataSource[]    // 数据源
  bindings: DataBinding[]      // 数据绑定
  metadata?: {                 // 元数据
    createdAt?: string
    updatedAt?: string
    author?: string
  }
}

// 画布 Schema
interface SchemaCanvas {
  width: number
  height: number
  backgroundColor?: string
  backgroundImage?: string
}

// 组件 Schema 结构 - 递归定义
interface SchemaComponent {
  id: string                   // 唯一标识
  type: string                 // 组件类型：text, button, input...
  name: string                 // 组件名称（显示用）
  style: SchemaStyle           // 样式：位置、大小、颜色等
  props: Record<string, any>   // 组件属性（文本内容、选项列表等）
  children?: SchemaComponent[] // 子组件（支持嵌套，递归结构）
  locked?: boolean             // 是否锁定
  visible?: boolean            // 是否可见
}

// 样式 Schema
interface SchemaStyle {
  x: number                    // 水平位置
  y: number                    // 垂直位置
  width: number                // 宽度
  height: number               // 高度
  rotate?: number              // 旋转角度
  opacity?: number             // 透明度
  borderWidth?: number         // 边框宽度
  borderColor?: string         // 边框颜色
  borderStyle?: string         // 边框样式
  borderRadius?: number        // 圆角
  backgroundColor?: string     // 背景色
  boxShadow?: string           // 阴影
  zIndex: number               // 层级
}
```

**为什么 Schema 要这样设计？**

1. **递归结构**：`children` 字段也是 `SchemaComponent[]`，支持无限嵌套
2. **style 和 props 分离**：style 是通用样式（位置、大小），props 是组件特有属性（文本内容、选项列表）
3. **version 字段**：保证向后兼容，新版本渲染器能解析旧版本 Schema

**渲染器独立打包配置**：

```typescript
// packages/renderer/vite.config.ts
export default defineConfig({
  build: {
    lib: {
      entry: resolve(__dirname, 'src/index.ts'),
      name: 'DevFlowRenderer',
      formats: ['es', 'umd'],  // 两种格式
      fileName: (format) => `devflow-renderer.${format}.js`
    },
    rollupOptions: {
      // 关键：外部依赖不打包进去
      external: ['vue', 'element-plus', 'echarts'],
      output: {
        globals: {
          vue: 'Vue',           // UMD 格式下 Vue 的全局变量名
          'element-plus': 'ElementPlus',
          echarts: 'echarts'
        }
      }
    },
    minify: 'terser',          // 压缩
    terserOptions: {
      compress: {
        drop_console: true,    // 移除 console
        drop_debugger: true    // 移除 debugger
      }
    }
  }
})
```

**为什么要 external？**

> 如果把 Vue 打包进渲染器，用户项目里也有 Vue，就会有两个 Vue 实例，导致：
> 1. 包体积翻倍
> 2. 响应式系统失效（两个 Vue 的 reactive 不互通）
> 3. 插件系统冲突
> 
> 所以必须把 Vue 等作为 `peerDependencies`，让用户项目自己提供。

**渲染器核心组件**：

```vue
<!-- SchemaRenderer.vue -->
<script setup lang="ts">
import { computed, defineAsyncComponent, markRaw } from 'vue'

const props = defineProps<{
  schema: SchemaPage
  mode?: 'preview' | 'edit'
  eventBindings?: EventBinding[]
  dataSources?: DataSource[]
  bindings?: DataBinding[]
}>()

const emit = defineEmits<{
  (e: 'event', componentId: string, eventType: string, event: Event): void
}>()

// 异步加载组件 - 按需加载，优化首屏
const TextComponent = markRaw(defineAsyncComponent(() => import('./components/TextComponent.vue')))
const ImageComponent = markRaw(defineAsyncComponent(() => import('./components/ImageComponent.vue')))
// ... 其他组件

// 组件映射表
const componentMap: Record<string, any> = {
  text: TextComponent,
  image: ImageComponent,
  // ...
}

// 按 zIndex 排序，保证层级正确
const sortedComponents = computed(() => {
  if (!props.schema?.components) return []
  return [...props.schema.components].sort((a, b) => a.style.zIndex - b.style.zIndex)
})

// 处理组件事件
function handleComponentEvent(componentId: string, eventType: string, event: Event) {
  // 1. 向外抛出事件
  emit('event', componentId, eventType, event)
  
  // 2. 查找事件绑定配置
  if (props.eventBindings) {
    const binding = props.eventBindings.find(b => b.componentId === componentId)
    if (binding) {
      const matchedEvent = binding.events.find(e => e.type === eventType && e.enabled)
      if (matchedEvent) {
        executeActions(matchedEvent.actions, { componentId, eventType })
      }
    }
  }
}
</script>

<template>
  <div class="schema-renderer" :style="containerStyle">
    <template v-for="component in sortedComponents" :key="component.id">
      <div :style="getComponentStyle(component)" @click="handleComponentEvent(component.id, 'click', $event)">
        <component :is="getComponentType(component.type)" :component="component" :mode="mode" />
      </div>
    </template>
  </div>
</template>
```

**为什么用 markRaw + defineAsyncComponent？**

> - `defineAsyncComponent`：异步加载，只在需要时才下载组件代码，优化首屏
> - `markRaw`：告诉 Vue 不要对这个组件对象做响应式代理，避免不必要的性能开销
> 
> 如果不用 markRaw，Vue 会把组件对象变成响应式的，这是没有意义的，反而浪费性能。

### 1.3 面试问答

**Q: 为什么要分离设计器和渲染器？**

> A: 主要有三个原因：
> 1. **复用性**：渲染器可以独立集成到其他项目，比如后台管理系统、营销活动页面生成器
> 2. **可维护性**：设计器和渲染器职责分离，代码更清晰
> 3. **体积优化**：渲染器只包含渲染逻辑，体积小（~15KB gzip），适合集成

**Q: Schema JSON 规范是怎么设计的？**

> A: Schema 分为三层：
> 1. **页面层**：包含画布配置、组件列表、事件、数据源
> 2. **组件层**：包含类型、样式、属性、子组件（递归定义）
> 3. **样式层**：包含位置、大小、颜色等具体样式值
> 
> 关键设计决策：
> - style 和 props 分离：style 是通用样式，props 是组件特有属性
> - children 递归：支持无限嵌套
> - version 字段：保证向后兼容

**Q: 渲染器独立打包遇到了什么问题？**

> A: 主要问题是依赖处理。Vue、Element Plus、ECharts 不能打包进去，否则会：
> 1. 导致两个 Vue 实例，响应式系统失效
> 2. 包体积翻倍
> 3. 插件系统冲突
> 
> 解决方案是把它们作为 `peerDependencies`，在 `vite.config.ts` 中配置 `external`，让用户项目自己提供这些依赖。

**Q: 渲染器如何保证版本兼容？**

> A: 通过 Schema 的 `version` 字段。渲染器会检查版本号，如果版本不匹配会提示用户升级。同时保持向下兼容，新版本渲染器能解析旧版本 Schema。

**Q: 为什么渲染器组件用异步加载？**

> A: 性能优化。用户可能只用到了文本和按钮组件，不需要加载图表、表格等组件的代码。异步加载实现了按需加载，减少首屏体积。配合 `markRaw` 避免不必要的响应式代理开销。

## 亮点二：动态组件递归渲染引擎

### 核心概念

- **动态组件**：根据 JSON 中的 `type` 字段，动态选择对应的 Vue 组件渲染
- **递归渲染**：容器组件内部可以包含子组件，子组件也可以是容器，形成树形结构
- **组件映射**：`type: 'text'` → `TextComponent`，通过映射表解耦类型和组件

### 2.1 为什么这样做？

**问题背景**：

- 低代码平台需要支持多种组件类型，且数量会不断增加
- 容器组件（如弹性布局、栅格布局）需要支持无限嵌套
- 需要将 JSON 配置动态渲染为真实的 Vue 组件

**解决方案**：

- 使用 Vue 的 `component :is` 动态组件特性
- 设计组件映射表，将组件类型映射到实际的 Vue 组件
- 通过递归渲染实现容器组件的嵌套

**类比理解**：
> 就像 React 中的条件渲染，但更优雅。不用写一堆 if-else，而是用一个映射表：
> `type = 'text'` → 渲染 TextComponent
> `type = 'button'` → 渲染 ButtonComponent
> 这就是"数据驱动渲染"的核心思想。

### 2.2 具体实现

**组件映射表**：

```typescript
// RenderComponent.vue
// 映射表：组件类型 → Vue 组件
const componentMap: Record<string, any> = {
  text: TextComponent,
  image: ImageComponent,
  button: ButtonComponent,
  input: InputComponent,
  textarea: TextareaComponent,
  select: SelectComponent,
  checkbox: CheckboxComponent,
  radio: RadioComponent,
  switch: SwitchComponent,
  datePicker: DatePickerComponent,
  chart: ChartComponent,
  container: ContainerComponent,  // Flex 容器
  grid: GridComponent,            // Grid 布局
  table: TableComponent
}

// 根据组件类型获取对应的 Vue 组件
// 如果类型不存在，降级为 TextComponent
const currentComponent = computed(() => 
  componentMap[props.component.type] || TextComponent
)
```

**动态渲染核心代码**：

```vue
<!-- RenderComponent.vue - 编辑器中的渲染组件 -->
<template>
  <div
    ref="componentRef"

    :class="{ selected, dragging, resizing, rotating }"
    :style="componentStyle"
    @mousedown="handleMouseDown"
    @contextmenu="handleContextMenu"

        :component="component"
        :highlighted="highlighted"

        <el-icon><Refresh /></el-icon>
      </div>
    </template>
  </div>
</template>
```

**`component :is` 的底层原理**：

```
用户操作 → JSON Schema 变化 → computed 重新计算 currentComponent
→ Vue 创建新的 VNode（createVNode） → 渲染为真实 DOM
```

> Vue 的 `component :is` 本质上是调用了 `createVNode(componentObject, props)` 来创建虚拟节点。
> 当 `currentComponent` 变化时，Vue 会销毁旧组件实例，创建新组件实例。
> 这就是为什么切换组件类型时，组件内部状态会重置。

**容器组件的递归渲染**：

### 2.3 遇到的问题与解决

**问题1：递归渲染导致栈溢出**

- **原因**：组件 A 的 children 包含组件 A 自己，形成循环引用
- **解决**：在渲染时检查层级深度，超过限制（如10层）停止渲染并警告

```typescript
// 递归深度检查
const MAX_DEPTH = 10

function renderComponent(component: SchemaComponent, depth: number = 0) {
  if (depth > MAX_DEPTH) {
    console.warn('组件嵌套深度超过限制，可能存在循环引用')
    return null
  }
  
  // 递归渲染子组件时，深度 +1
  if (component.children) {
    component.children.forEach(child => renderComponent(child, depth + 1))
  }
}
```

**问题2：子组件样式相对于父容器定位**

- **原因**：子组件的 x、y 是相对于父容器的，需要转换
- **解决**：在添加子组件时，将坐标转换为相对坐标

```typescript
// 添加子组件到容器时，坐标转换
function addChildToContainer(containerId: string, child: EditorComponent) {
  const container = getComponentById(containerId)
  
  // 绝对坐标 → 相对坐标
  const newChild = {
    ...child,
    parentId: containerId,
    style: {
      ...child.style,
      x: child.style.x - container.style.x,  // 相对于容器左上角
      y: child.style.y - container.style.y
    }
  }
}

// 从容器移出子组件时，坐标还原
function removeChildFromContainer(containerId: string, childId: string) {
  const container = getComponentById(containerId)
  const child = container.children.find(c => c.id === childId)
  
  // 相对坐标 → 绝对坐标
  const restoredChild = {
    ...child,
    parentId: undefined,
    style: {
      ...child.style,
      x: child.style.x + container.style.x,  // 加上容器的偏移
      y: child.style.y + container.style.y
    }
  }
}
```

**问题3：容器内子组件无法选中编辑**

- **原因**：点击子组件时，事件冒泡到容器，容器被选中而不是子组件
- **解决**：事件冒泡时检查点击目标，如果点击的是子组件则选中子组件

```typescript
// 容器内子组件的点击处理
function handleChildSelect(childId: string, e: MouseEvent) {
  e.stopPropagation()  // 阻止冒泡到容器
  componentStore.selectComponent(childId, e.ctrlKey || e.metaKey)
}
```

### 2.4 面试问答

**Q: `component :is` 的原理是什么？**

> A: `component :is` 是 Vue 的内置组件，根据传入的组件名或组件对象动态渲染对应的组件。底层会调用 Vue 的 `createVNode` 函数创建虚拟节点，然后渲染为真实 DOM。
> 
> 它的好处是不需要写大量的 `v-if/v-else` 来判断组件类型，代码更简洁、可维护。
> 
> 注意点：当 `is` 的值变化时，Vue 会销毁旧组件实例并创建新实例，组件内部状态会重置。如果需要保留状态，可以用 `<KeepAlive>` 包裹。

**Q: 递归渲染如何避免无限循环？**

> A: 我们做了两层保护：
> 1. **数据层**：在添加子组件时检查是否形成循环引用（A 的 children 不能包含 A 自己）
> 2. **渲染层**：递归时检查深度，超过10层停止渲染并输出警告
> 
> 实际上，用户不太可能创建超过10层的嵌套，这个限制主要是防止数据异常导致的无限循环。

**Q: 如何支持新的组件类型？**

> A: 只需要三步：
> 1. 创建新的 Vue 组件（如 `NewComponent.vue`）
> 2. 在 `componentMap` 中添加映射：`newType: NewComponent`
> 3. 在组件面板中添加对应的拖拽项
> 
> 这样新组件就能被动态渲染了，体现了系统的**开闭原则**（对扩展开放，对修改关闭）。

**Q: 子组件的坐标为什么要做转换？**

> A: 因为子组件的坐标是相对于父容器的，而不是相对于画布的。
> 
> 举个例子：容器在画布上的位置是 (100, 100)，子组件在容器内的位置是 (10, 10)，那么子组件在画布上的实际位置是 (110, 110)。
> 
> 拖入容器时：绝对坐标 → 相对坐标（减去容器位置）
> 拖出容器时：相对坐标 → 绝对坐标（加上容器位置）
> 
> 这和 CSS 的 `position: relative/absolute` 是同一个原理。

## 亮点三：可视化事件与数据绑定系统

### 核心概念

- **事件 DSL**：用 JSON 描述"什么事件触发什么动作"，不存储 JS 代码
- **数据绑定**：将数据源（API/静态/变量）绑定到组件属性，数据变化时组件自动更新
- **安全执行**：通过 switch-case 解析动作，不用 eval，防止 XSS

### 3.1 为什么这样做？

**问题背景**：

- 低代码不仅要配置 UI，还要配置交互逻辑
- 直接存储 JS 代码字符串存在安全风险（XSS 攻击）
- 用户可能不懂编程，需要可视化配置方式

**解决方案**：

- 设计事件 DSL（领域特定语言），用 JSON 描述事件和动作
- 提供可视化配置界面，用户通过表单配置交互
- 在渲染端安全解析执行，不使用 `eval`

**类比理解**：
> 事件 DSL 就像 iOS 的快捷指令：你不需要写代码，只需要选择"触发条件"和"执行动作"。
> 
> 比如：点击按钮 → 发送消息 → 跳转页面
> 
> 对应 JSON：
> ```json
> { "type": "click", "actions": [
>   { "type": "showMessage", "config": { "message": "提交成功" } },
>   { "type": "navigate", "config": { "url": "/success" } }
> ]}
> ```

### 3.2 具体实现

**事件 DSL 设计**：

```typescript
async function executeActions(actions: EventAction[], context: any) {
  for (const action of actions) {
    if (!action.enabled) continue
    
    try {
      switch (action.type) {
        case 'navigate':
          // 安全：只允许跳转，不能执行任意代码
          window.open(action.config.url, action.config.target || '_blank')
          break
          
        case 'showMessage':
          // 安全：只显示预定义的消息
          ElMessage({ message: action.config.message, type: action.config.type || 'info' })
          break
          
        case 'setVariable':
          // 安全：只修改变量值，不能执行函数
          globalVariables.value[action.config.variableName] = action.config.value
          break
          
        case 'apiRequest':
          // 安全：只发 HTTP 请求，不能执行任意代码
          const response = await fetch(action.config.url, {
            method: action.config.method || 'GET',
            headers: action.config.headers,
            body: action.config.body ? JSON.stringify(action.config.body) : undefined
          })
          const data = await response.json()
          updateBindings(action.config.dataSourceId, data)
          break
          
        case 'showComponent':
        case 'hideComponent':
        case 'toggleComponent':
          // 安全：只控制组件可见性
          updateComponentVisibility(action.config.targetId, ...)
          break
      }
    } catch (error) {
      console.error('Action execution failed:', error)
      // 错误不会中断其他动作的执行
    }
  }
}
```

### 3.3 面试问答

**Q: 为什么不用 eval 执行事件代码？**

> A: 安全原因。如果存储 JS 代码字符串，存在 XSS 攻击风险：
> 1. 恶意用户可能注入恶意代码（如窃取 cookie、发送请求到恶意服务器）
> 2. 代码执行环境不可控，可能影响整个应用
> 3. 难以调试和追踪
> 
> 使用 DSL + switch-case 的方式：
> 1. 只执行预定义的动作，安全可控
> 2. 可以添加权限控制和日志记录
> 3. 易于调试，错误可追踪
> 
> 这本质上是一种**沙箱**思想：限制代码的能力范围，只允许执行安全的操作。

**Q: 数据绑定是如何实现的？**

> A: 数据绑定分为三步：
> 1. **数据源管理**：创建静态数据、API 或全局变量数据源
> 2. **绑定配置**：将数据源绑定到组件的某个属性
> 3. **数据更新**：当数据源变化时，自动更新绑定的组件
> 
> 实现上利用 Vue 的响应式系统：
> - 数据源用 `ref` 存储，变化时触发依赖更新
> - 组件属性通过 `computed` 关联数据源
> - API 数据源用 `fetch` 获取，获取后更新 `ref`

**Q: 如何处理异步数据加载？**

> A: API 数据源是异步的，我们做了以下处理：
> 1. 组件初始渲染时显示 loading 状态
> 2. 数据加载完成后更新组件
> 3. 加载失败显示错误提示，支持重试
> 4. 支持配置 `refreshInterval`，定时刷新数据

**Q: 事件系统如何支持复杂逻辑？**

> A: 虽然单个动作比较简单，但可以通过组合实现复杂逻辑：
> 1. 一个事件可以绑定多个动作，按顺序执行
> 2. 动作可以设置执行条件（condition）
> 3. API 请求动作可以触发数据更新，进而触发其他组件变化
> 4. 支持全局变量，实现跨组件通信
> 
> 这是一种**声明式编程**思想：用户描述"做什么"，而不是"怎么做"。

## 亮点四：完整画布交互体系

### 核心概念

- **坐标转换**：屏幕坐标（鼠标位置）和画布坐标（组件位置）之间的转换
- **拖拽交互**：从组件面板拖入画布、画布内移动、拖入容器
- **缩放旋转**：8点缩放改变大小、旋转手柄改变角度
- **对齐吸附**：辅助线对齐、网格吸附，提高精度

### 4.1 坐标转换（最重要）

**为什么需要坐标转换？**

画布有缩放（scale）和平移（offset），但鼠标事件返回的是屏幕坐标，而组件的位置是画布坐标。

```
屏幕坐标系：鼠标在浏览器窗口中的位置
画布坐标系：组件在画布中的逻辑位置

两者之间的关系：
画布通过 CSS transform 实现缩放和平移：
transform: translate(offsetX, offsetY) scale(scale)

所以：
屏幕坐标 = 画布坐标 × scale + offset + 容器位置
画布坐标 = (屏幕坐标 - offset - 容器位置) / scale
```

**具体公式**：

```typescript
// 屏幕坐标 → 画布坐标（最常用）
// 在所有鼠标事件中都需要这个转换
function screenToCanvas(clientX: number, clientY: number) {
  const rect = canvasContainer.value.getBoundingClientRect()
  return {
    x: (clientX - rect.left - editorStore.canvas.offsetX) / editorStore.canvas.scale,
    y: (clientY - rect.top - editorStore.canvas.offsetY) / editorStore.canvas.scale
  }
}

// 画布坐标 → 屏幕坐标（少用）
function canvasToScreen(canvasX: number, canvasY: number) {
  const rect = canvasContainer.value.getBoundingClientRect()
  return {
    x: canvasX * editorStore.canvas.scale + rect.left + editorStore.canvas.offsetX,
    y: canvasY * editorStore.canvas.scale + rect.top + editorStore.canvas.offsetY
  }
}
```

**公式推导**：

```
画布的 CSS transform: translate(offsetX, offsetY) scale(scale)

一个画布坐标为 (cx, cy) 的点，在屏幕上的位置是：
screenX = cx * scale + offsetX + rect.left
screenY = cy * scale + offsetY + rect.top

反过来，已知屏幕坐标求画布坐标：
cx = (screenX - rect.left - offsetX) / scale
cy = (screenY - rect.top - offsetY) / scale
```

**在哪些地方用到了坐标转换？**

| 场景 | 事件 | 转换方向 |
|-----|------|---------|
| 拖入组件 | dragover, drop | 屏幕 → 画布 |
| 移动组件 | mousemove | 屏幕 → 画布 |
| 缩放组件 | mousemove | 屏幕 → 画布 |
| 旋转组件 | mousemove | 屏幕 → 画布 |
| 框选组件 | mousedown, mousemove | 屏幕 → 画布 |

```typescript
function findContainerAtPosition(x: number, y: number, excludeId?: string): EditorComponent | null {
  // 找到所有容器组件
  const containers = components.value.filter(c =>
    (c.type === 'container' || c.type === 'grid') &&
    c.id !== excludeId &&
    c.visible !== false
  )
  
  // 检查点是否在容器范围内
  for (const container of containers) {
    const { x: cx, y: cy, width, height } = container.style
    if (x >= cx && x <= cx + width && y >= cy && y <= cy + height) {
      return container
    }
  }
  return null
}
```

### 4.3 8点缩放

```typescript
// 8个控制点
const resizeHandles = [
  { type: 'nw', cursor: 'nwse-resize' },  // 左上角
  { type: 'n',  cursor: 'ns-resize' },    // 上边中点
  { type: 'ne', cursor: 'nesw-resize' },  // 右上角
  { type: 'e',  cursor: 'ew-resize' },    // 右边中点
  { type: 'se', cursor: 'nwse-resize' },  // 右下角
  { type: 's',  cursor: 'ns-resize' },    // 下边中点
  { type: 'sw', cursor: 'nesw-resize' },  // 左下角
  { type: 'w',  cursor: 'ew-resize' }     // 左边中点
]

function handleResizeStart(e: MouseEvent, handle: string) {
  e.stopPropagation()
  isResizing.value = true
  resizeHandle.value = handle
  
  // 记录起始状态
  resizeStart.value = {
    x: e.clientX,
    y: e.clientY,
    width: props.component.style.width,
    height: props.component.style.height,
    left: props.component.style.x,
    top: props.component.style.y
  }
}

function handleMouseMove(e: MouseEvent) {
  if (!isResizing.value) return
  
  // 关键：鼠标位移也要除以 scale
  const deltaX = (e.clientX - resizeStart.value.x) / editorStore.canvas.scale
  const deltaY = (e.clientY - resizeStart.value.y) / editorStore.canvas.scale
  
  let newWidth = resizeStart.value.width
  let newHeight = resizeStart.value.height
  let newX = resizeStart.value.left
  let newY = resizeStart.value.top
  
  // 根据手柄方向计算新尺寸
  // e = 右边，增加宽度
  if (resizeHandle.value.includes('e')) {
    newWidth = Math.max(20, resizeStart.value.width + deltaX)
  }
  // w = 左边，增加宽度但 x 也要变
  if (resizeHandle.value.includes('w')) {
    newWidth = Math.max(20, resizeStart.value.width - deltaX)
    newX = resizeStart.value.left + deltaX
  }
  // s = 下边，增加高度
  if (resizeHandle.value.includes('s')) {
    newHeight = Math.max(20, resizeStart.value.height + deltaY)
  }
  // n = 上边，增加高度但 y 也要变
  if (resizeHandle.value.includes('n')) {
    newHeight = Math.max(20, resizeStart.value.height - deltaY)
    newY = resizeStart.value.top + deltaY
  }
  
  // Math.max(20, ...) 保证最小尺寸为 20px
  
  componentStore.updateComponentStyle(props.component.id, {
    width: newWidth, height: newHeight, x: newX, y: newY
  })
}
```

**为什么拖左边/上边时 x/y 也要变？**

> 想象一下：拖拽左边手柄向左拉，宽度增加了，但右边的位置不能变，所以左边的 x 要减小。
> 
> 拖拽右边手柄向右拉，宽度增加了，左边的位置不变，所以 x 不变。
> 
> 这就是为什么 `w` 和 `n` 方向需要同时调整位置。

### 4.4 旋转功能

```typescript
function handleRotateStart(e: MouseEvent) {
  isRotating.value = true
  
  // 计算组件中心点（屏幕坐标）
  const rect = componentRef.value.getBoundingClientRect()
  const centerX = rect.left + rect.width / 2
  const centerY = rect.top + rect.height / 2
  
  // 计算鼠标相对于中心点的初始角度
  // Math.atan2 返回弧度，需要转换为角度
  rotateStart.value = {
    angle: props.component.style.rotate,  // 当前旋转角度
    startAngle: Math.atan2(e.clientY - centerY, e.clientX - centerX) * (180 / Math.PI)
  }
}

function handleMouseMove(e: MouseEvent) {
  if (!isRotating.value) return
  
  const rect = componentRef.value.getBoundingClientRect()
  const centerX = rect.left + rect.width / 2
  const centerY = rect.top + rect.height / 2
  
  // 计算当前角度
  const currentAngle = Math.atan2(e.clientY - centerY, e.clientX - centerX) * (180 / Math.PI)
  
  // 角度变化 = 当前角度 - 初始角度
  const deltaAngle = currentAngle - rotateStart.value.startAngle
  
  // 新旋转角度 = 原始角度 + 角度变化
  let newRotation = Math.round(rotateStart.value.angle + deltaAngle)
  
  // 按住 Shift 时，吸附到 15 度的整数倍
  if (e.shiftKey) {
    newRotation = Math.round(newRotation / 15) * 15
  }
  
  componentStore.setComponentRotation(props.component.id, newRotation)
}
```

**Math.atan2 的原理**：

```
atan2(y, x) 返回点 (x, y) 与正 x 轴之间的角度（弧度）

         0°
          |
   -90° --+-- 90°
          |
       ±180°

例如：
- 鼠标在中心右边 → atan2 返回 0°
- 鼠标在中心上方 → atan2 返回 -90°
- 鼠标在中心左边 → atan2 返回 ±180°
```

### 4.5 对齐辅助线

```typescript
function calculateAlignmentLines(x: number, y: number, width: number, height: number) {
  const threshold = 5  // 对齐阈值：5px 以内显示辅助线
  const lines = { horizontal: [], vertical: [] }
  
  // 1. 检测与画布边缘的对齐
  if (Math.abs(x) < threshold) lines.vertical.push(0)                    // 左边对齐
  if (Math.abs(x + width - canvasWidth) < threshold) lines.vertical.push(canvasWidth)  // 右边对齐
  if (Math.abs(x + width/2 - canvasWidth/2) < threshold) lines.vertical.push(canvasWidth/2)  // 水平居中
  
  if (Math.abs(y) < threshold) lines.horizontal.push(0)                  // 上边对齐
  if (Math.abs(y + height - canvasHeight) < threshold) lines.horizontal.push(canvasHeight) // 下边对齐
  if (Math.abs(y + height/2 - canvasHeight/2) < threshold) lines.horizontal.push(canvasHeight/2) // 垂直居中
  
  // 2. 检测与其他组件的对齐
  components.forEach(comp => {
    if (comp.id === currentComponentId) return  // 跳过自己
    
    // 垂直方向对齐（6种情况）
    if (Math.abs(x - comp.style.x) < threshold)                          // 左-左
      lines.vertical.push(comp.style.x)
    if (Math.abs(x + width - comp.style.x) < threshold)                  // 右-左
      lines.vertical.push(comp.style.x)
    if (Math.abs(x - comp.style.x - comp.style.width) < threshold)       // 左-右
      lines.vertical.push(comp.style.x + comp.style.width)
    if (Math.abs(x + width - comp.style.x - comp.style.width) < threshold) // 右-右
      lines.vertical.push(comp.style.x + comp.style.width)
    if (Math.abs(x + width/2 - comp.style.x - comp.style.width/2) < threshold) // 中心-中心
      lines.vertical.push(comp.style.x + comp.style.width / 2)
    
    // 水平方向对齐（同理6种）
    // ...
  })
  
  // 去重
  return {
    horizontal: [...new Set(lines.horizontal)],
    vertical: [...new Set(lines.vertical)]
  }
}
```

```typescript
  const rect = canvasContainer.value.getBoundingClientRect()
  const x = (e.clientX - rect.left - offsetX) / scale  // 坐标转换
  const y = (e.clientY - rect.top - offsetY) / scale
  
  selectionBox.value = { startX: x, startY: y, endX: x, endY: y }
  componentStore.clearSelection()
}

function handleMouseMove(e: MouseEvent) {
  if (!selectionBox.value) return
  
  const rect = canvasContainer.value.getBoundingClientRect()
  selectionBox.value.endX = (e.clientX - rect.left - offsetX) / scale
  selectionBox.value.endY = (e.clientY - rect.top - offsetY) / scale
}

function handleMouseUp() {
  if (!selectionBox.value) return
  
  const box = selectionBox.value
  const minX = Math.min(box.startX, box.endX)
  const maxX = Math.max(box.startX, box.endX)
  const minY = Math.min(box.startY, box.endY)
  const maxY = Math.max(box.startY, box.endY)
  
  // 检测哪些组件在选框内
  components.forEach(comp => {
    if (comp.locked || comp.visible === false) return
    
    const compLeft = comp.style.x
    const compRight = comp.style.x + comp.style.width
    const compTop = comp.style.y
    const compBottom = comp.style.y + comp.style.height
    const centerX = (compLeft + compRight) / 2
    const centerY = (compTop + compBottom) / 2
    
    // 三种检测方式，任一满足即选中
    const centerInBox = centerX >= minX && centerX <= maxX && centerY >= minY && centerY <= maxY
    const boxInComp = minX >= compLeft && maxX <= compRight && minY >= compTop && maxY <= compBottom
    const intersects = !(compRight < minX || compLeft > maxX || compBottom < minY || compTop > maxY)
    
    if (centerInBox || boxInComp || intersects) {
      componentStore.selectComponent(comp.id, true)
    }
  })
  
  selectionBox.value = null
}

// 组合 - 将多个组件合并为一个容器
function groupComponents(ids: string[]) {
  const selectedComps = components.filter(c => ids.includes(c.id))
  
  // 计算组合的边界框
  const minX = Math.min(...selectedComps.map(c => c.style.x))
  const minY = Math.min(...selectedComps.map(c => c.style.y))
  const maxX = Math.max(...selectedComps.map(c => c.style.x + c.style.width))
  const maxY = Math.max(...selectedComps.map(c => c.style.y + c.style.height))
  
  // 创建组合容器
  const group = {
    id: uuidv4(),
    type: 'container',
    style: { x: minX, y: minY, width: maxX - minX, height: maxY - minY },
    children: selectedComps.map(c => ({
      ...c,
      style: { ...c.style, x: c.style.x - minX, y: c.style.y - minY }  // 相对坐标
    }))
  }
  
  // 替换原组件
  components = [...components.filter(c => !ids.includes(c.id)), group]
}
```

### 4.7 面试问答

**Q: 坐标转换的原理是什么？**

> A: 画布有缩放（scale）和平移（offset），鼠标事件的坐标是屏幕坐标，需要转换为画布坐标。
> 
> 转换公式：`canvasX = (clientX - rect.left - offsetX) / scale`
> 
> 推导过程：
> 1. 画布通过 CSS `transform: translate(offsetX, offsetY) scale(scale)` 实现缩放和平移
> 2. 所以屏幕坐标 = 画布坐标 × scale + offset + 容器位置
> 3. 反过来就是画布坐标 = (屏幕坐标 - offset - 容器位置) / scale
> 
> 这个公式本质上是一个逆矩阵变换，将屏幕坐标系的点映射到画布坐标系。

**Q: 8点缩放如何实现？**

> A: 8个控制点对应8个方向：
> - 角点（nw, ne, sw, se）：同时改变宽度和高度
> - 边点（n, s, e, w）：只改变一个方向
> 
> 关键细节：
> - 拖拽左边/上边时，x/y 也要跟着变（因为对面的边不动）
> - 鼠标位移要除以 scale（因为画布可能缩放了）
> - 最小尺寸限制为 20px，防止缩成负数

**Q: 旋转角度怎么计算的？**

> A: 使用 `Math.atan2(dy, dx)` 计算鼠标相对于组件中心的角度。
> 
> 1. 获取组件中心点的屏幕坐标
> 2. 计算鼠标按下时的初始角度
> 3. 移动时计算当前角度
> 4. 旋转角度 = 原始角度 + (当前角度 - 初始角度)
> 5. 按住 Shift 时吸附到 15° 的整数倍

**Q: 对齐辅助线如何提高精度？**

> A: 对齐辅助线通过实时计算，在拖拽时显示：
> 1. 与画布边缘的对齐（左、右、上、下、中心）
> 2. 与其他组件的对齐（边缘、中心）
> 
> 设置阈值 5px，距离小于 5px 时显示辅助线。这是 Figma、Sketch 等专业设计工具的标准功能。

**Q: 框选时为什么用三种检测方式？**

> A: 因为不同场景需要不同的检测逻辑：
> 1. **中心点检测**：最常用，选框包含组件中心就算选中
> 2. **包含检测**：选框很小但完全在组件内部时也能选中
> 3. **相交检测**：选框和组件有交集就算选中，不会漏选
> 
> 三种方式取并集，确保各种框选场景都能正确选中。

## 亮点五：性能优化与撤销重做

### 核心概念

- **shallowRef**：浅层响应式，只追踪 `.value` 的变化，不深度追踪内部属性
- **不可变数据**：每次更新都创建新对象，不直接修改原数据
- **防抖快照**：延迟保存历史记录，连续操作只保存最终状态

### 5.1 shallowRef vs ref

**ref 的工作原理**：

```typescript
// ref：深度响应式
const components = ref([{ id: '1', style: { x: 100, y: 200 } }])

// Vue 会递归地把对象的所有属性变成响应式：
// components.value → reactive(Array)
// components.value[0] → reactive(Object)
// components.value[0].style → reactive(Object)
// components.value[0].style.x → reactive(Number)  ← 不需要！
// components.value[0].style.y → reactive(Number)  ← 不需要！
//
// 100 个组件 × 每个组件 20+ 属性 = 2000+ 个响应式对象
// 这就是性能瓶颈！
```

**shallowRef 的工作原理**：

```typescript
// shallowRef：浅层响应式
const components = shallowRef([{ id: '1', style: { x: 100, y: 200 } }])

// Vue 只追踪 .value 的变化：
// components.value → 只追踪引用变化
// components.value[0] → 不追踪
// components.value[0].style → 不追踪
// components.value[0].style.x → 不追踪
//
// 只有当 .value 被赋值为新数组时，才触发更新
```

**更新方式的区别**：

```typescript
// ❌ ref 的更新方式（直接修改）
components.value[0].style.x = 200  // 触发更新

// ❌ shallowRef 不能这样更新（不会触发更新）
components.value[0].style.x = 200  // 不会触发更新！

// ✅ shallowRef 的正确更新方式（创建新数组）
components.value = [
  { ...components.value[0], style: { ...components.value[0].style, x: 200 } },
  ...components.value.slice(1)
]
// .value 被赋值为新数组 → 触发更新！
```

**封装后的更新函数**：

```typescript
function updateComponent(id: string, updates: Partial<EditorComponent>) {
  const index = components.value.findIndex(c => c.id === id)
  if (index > -1) {
    // 创建新数组，替换目标组件
    components.value = [
      ...components.value.slice(0, index),
      { ...components.value[index], ...updates },  // 创建新对象
      ...components.value.slice(index + 1)
    ]
    // 赋值新数组 → shallowRef 检测到 .value 变化 → 触发更新
  }
}

function updateComponentStyle(id: string, styleUpdates: Partial<ComponentStyle>) {
  const index = components.value.findIndex(c => c.id === id)
  if (index > -1) {
    components.value = [
      ...components.value.slice(0, index),
      { ...components.value[index], style: { ...components.value[index].style, ...styleUpdates } },
      ...components.value.slice(index + 1)
    ]
  }
}
```

### 5.2 不可变数据模式

**为什么需要不可变数据？**

```typescript
// 问题：可变数据导致历史记录被污染
const snapshot = [{ id: '1', style: { x: 100 } }]  // 保存快照
const component = components.value[0]
component.style.x = 200  // 直接修改

// 快照也被修改了！因为它们引用同一个对象
console.log(snapshot[0].style.x)  // 200，不是 100！
```

```typescript
// 解决：不可变数据
function updateComponentStyle(id: string, styleUpdates: Partial<ComponentStyle>) {
  // 创建新对象，不修改原对象
  components.value = [
    ...components.value.slice(0, index),
    { ...components.value[index], style: { ...components.value[index].style, ...styleUpdates } },
    ...components.value.slice(index + 1)
  ]
  // 原对象不变，快照安全
}
```

**不可变数据的三个好处**：

1. **历史记录安全**：快照不会被后续操作修改
2. **Vue 响应式兼容**：shallowRef 需要新对象才能触发更新
3. **便于调试**：每次更新都是独立的，可以追踪变化

### 5.3 防抖快照

**为什么需要防抖？**

```
用户拖拽组件，每帧触发 mousemove（约 60 次/秒）

不防抖：
  0ms:  保存快照 { x: 0 }
  16ms: 保存快照 { x: 1 }
  33ms: 保存快照 { x: 2 }
  50ms: 保存快照 { x: 3 }
  ...   （1秒产生 60 个快照！）

防抖后：
  0ms:  设置定时器 300ms
  16ms: 清除旧定时器，设置新定时器 300ms
  33ms: 清除旧定时器，设置新定时器 300ms
  ...   （持续拖拽时不保存）
  300ms 后无操作：保存快照 { x: 最终位置 }
  （1次拖拽只产生 1 个快照）
```

**实现代码**：

```typescript
let saveTimer: ReturnType<typeof setTimeout> | null = null

function saveSnapshot(debounce: boolean = true) {
  if (debounce) {
    // 清除旧定时器（重新计时）
    if (saveTimer) {
      clearTimeout(saveTimer)
    }
    // 设置新定时器
    saveTimer = setTimeout(() => {
      performSave()
      saveTimer = null
    }, 300)  // 300ms 内无新操作才保存
  } else {
    // 不防抖，立即保存（如删除操作）
    performSave()
  }
}

function performSave() {
  const componentStore = useComponentStore()
  
  // 深拷贝当前状态
  const snapshot = componentStore.getComponentsSnapshot()
  
  // 如果之前有撤销操作，丢弃后面的历史
  // 比如：操作1 → 操作2 → 撤销到操作1 → 新操作3
  // 此时操作2 应该被丢弃
  const newSnapshots = currentIndex.value < snapshots.value.length - 1
    ? snapshots.value.slice(0, currentIndex.value + 1)
    : [...snapshots.value]
  
  newSnapshots.push(snapshot)
  
  // 限制最大历史记录
  if (newSnapshots.length > maxHistory) {
    newSnapshots.shift()  // 移除最早的
  } else {
    currentIndex.value++
  }
  
  snapshots.value = newSnapshots
}
```

**撤销/重做**：

```typescript
function undo() {
  if (currentIndex.value <= 0) return  // 没有可撤销的
  
  currentIndex.value--  // 指向上一个快照
  const componentStore = useComponentStore()
  componentStore.restoreFromSnapshot(snapshots.value[currentIndex.value])
}

function redo() {
  if (currentIndex.value >= snapshots.value.length - 1) return  // 没有可重做的
  
  currentIndex.value++  // 指向下一个快照
  const componentStore = useComponentStore()
  componentStore.restoreFromSnapshot(snapshots.value[currentIndex.value])
}
```

**快照的深拷贝**：

```typescript
function getComponentsSnapshot(): EditorComponent[] {
  // JSON 序列化/反序列化 = 深拷贝
  // 适用于纯数据对象（没有函数、循环引用）
  return JSON.parse(JSON.stringify(components.value))
}

function restoreFromSnapshot(snapshot: EditorComponent[]) {
  // 恢复时也要深拷贝，避免快照被修改
  components.value = JSON.parse(JSON.stringify(snapshot))
}
```

### 5.5 面试问答

**Q: 为什么用 shallowRef 而不是 ref？**

> A: 性能考虑。组件列表是大型数组，如果用 ref，Vue 会深度追踪每个组件对象的每个属性，100 个组件可能产生 2000+ 个响应式对象。
> 
> 使用 shallowRef，只追踪 `.value` 的变化，更新时创建新数组赋值即可触发响应式更新。
> 
> 这是一种权衡：牺牲了属性级别的细粒度更新，换取了整体性能的提升。对于组件列表这种场景是合适的，因为组件的属性变化通常通过 `updateComponentStyle` 等函数统一处理。

**Q: 为什么历史记录要防抖？**

> A: 用户拖拽组件时，每帧都会触发位置更新（约60次/秒）。如果不防抖：
> 1. 1秒产生 60 个快照，50步历史 1 秒就用完了
> 2. 大部分快照是中间状态（x=1, x=2, x=3...），没有意义
> 3. 撤销时需要跳过很多中间状态
> 
> 防抖 300ms 后，一次拖拽只保存最终状态，既节省内存，又提升了用户体验。

**Q: 为什么限制50步历史记录？**

> A: 历史记录存储在内存中，每个快照是组件树的深拷贝。不限制会导致：
> 1. 内存持续增长，可能造成页面卡顿
> 2. 用户很少需要回退超过50步
> 
> 50步是一个平衡点。如果需要更多，可以：
> 1. 增加到 100 步
> 2. 实现持久化存储（localStorage/IndexedDB）
> 3. 使用增量快照（只存储变化的部分）

**Q: 为什么用 JSON.parse/JSON.stringify 深拷贝？**

> A: 简单、可靠。组件数据是纯 JSON 对象，没有函数、循环引用等复杂情况，JSON 序列化足够。
> 
> 其他方案对比：
> - `structuredClone()`：浏览器原生 API，性能更好，但兼容性稍差
> - `lodash.cloneDeep()`：功能最全，但需要额外依赖
> - `JSON.parse/JSON.stringify`：最简单，无依赖，当前场景够用

**Q: 撤销后新操作，为什么丢弃后面的历史？**

> A: 这是标准的历史记录管理策略。比如：
> - 操作1 → 操作2 → 操作3
> - 撤销到操作2
> - 执行新操作4
> - 此时操作3 应该被丢弃
> 
> 如果不丢弃，历史记录会分叉，变成树形结构，用户会困惑"重做"到底是回到哪个状态。
> 
> 这和 Git 的原理一样：checkout 到旧 commit 后新建 commit，之前的 commit 就不在当前分支了。

> 3. **分片渲染**：大量组件时，分批渲染，避免一次性渲染导致卡顿
> 4. **Web Worker**：将对齐线计算等耗时操作放到 Worker 中执行
> 
> 目前我们的 shallowRef + 不可变数据方案，在 100 个组件以内性能良好，1000 个组件需要进一步优化。
